# Рядом

Android-приложение для двух человек: голос, чат и совместный просмотр экрана со звуком. Один участник показывает экран, второй смотрит; роли можно менять. Камера отложена. Минимум Android10; целевое устройство — Samsung Galaxy A54 (arm64). Для просмотра без акустического эха используйте наушники.

Захват звука зависит от приложения-источника: мод TikTok может запрещать Android Playback Capture. «Сигнал звука» показывает обнаруженный локальный звук, но сам по себе не доказывает, что второй телефон его слышит. Проверка на реальном Samsung и двух сетях ещё не выполнена.

## Обычный запуск: одна команда

Открой **терминал Ubuntu/WSL** на своём ПК:

```bash
git clone https://github.com/be0hhh/ryadom.git
cd ryadom
./run.sh
```

Первый запуск сам проверит зависимости. На Ubuntu недостающие пакеты и Tailscale устанавливаются **после твоего подтверждения**; для системных действий терминал попросит пароль `sudo`. Затем Tailscale покажет ссылку для входа: открой её в браузере и подтверди свой аккаунт. Скрипт получает адрес ПК, создаёт приватную конфигурацию, подготавливает сервер и фильтр media-портов, скачивает образ LiveKit и запускает сервисы. При необходимости отдельно спрашивает разрешение назначить текущего пользователя локальным оператором Tailscale. Чужого оператора не заменяет. При отсутствии доступа к Docker используется временная группа только для запуска, без `usermod` и постоянного изменения групп.

Если Tailscale уже включён на Windows, сначала отключи его там: этот вариант использует Tailscale внутри WSL. Если Serve попросит включить HTTPS, ссылка будет в `deploy/state/serve443.log` или `serve8443.log`; включи HTTPS в своём аккаунте и повтори `./run.sh`. Аккаунт, MagicDNS/HTTPS и доступ телефонов к tailnet подтверждает владелец аккаунта — скрипт не может сделать это за него.

После запуска терминал покажет **приватную ссылку настройки** и действия для телефонов. Последующие запуски используют сохранённую конфигурацию. При неизменных исходниках сервер заново не собирается; изменения и удаления файлов учитываются. ПК, WSL и терминал должны оставаться включёнными.

```bash
./run.sh stop    # остановить сервер из другого терминала; можно также Ctrl+C
./run.sh link    # ещё раз показать приватную ссылку настройки
./run.sh status  # проверить ответы локальных API, без утверждения о медиасвязи
./run.sh --help
```

На обоих телефонах:

1. Установите `dist/ryadom.apk` и приложение Tailscale. Подключите оба телефона к одному tailnet: пригласи второго человека в свою сеть Tailscale, не передавая пароль аккаунта. Включите Tailscale.
2. На своём телефоне открой «Рядом», введи имя, вставь приватную ссылку настройки из терминала → **«Создать комнату»**.
3. Нажми значок приглашения и отправь **ссылку комнаты** партнёру. Ему нужна эта ссылка, а не административная ссылка настройки.
4. Партнёр вводит имя, вставляет приглашение → **«Войти по приглашению»**.
5. Один нажимает **«Показать экран»**, подтверждает разрешение Android и открывает TikTok. Для смены ведущего сначала остановите текущий показ.

Локальная проверка launcher: `python3 -m unittest discover -s scripts -p test_launcher.py -v`. Эти тесты используют временные файлы, подставные внешние команды и короткий HTTP fixture; они не устанавливают зависимости и не включают реальный Docker/Tailscale. Реальный первый запуск этого сценария и просмотр на телефонах пока не выполнены.

## Сборка и локальные проверки

Из Linux-каталога проекта в WSL2 (не `/mnt/c`):

```bash
bash scripts/bootstrap.sh
./gradlew :server:test :app:testDebugUnitTest
./gradlew :app:lintDebug :app:assembleDebug
```

Bootstrap размещает инструменты в `.tools/`. APK: `app/build/outputs/apk/debug/app-debug.apk`; копия для передачи — `dist/ryadom.apk`, если она подготовлена при сборке. Это debug APK для ручной установки, без встроенного ключа сервера. Установку и разрешения Android пользователь подтверждает на каждом телефоне.

## Домашний сервер в WSL2

Ниже — детали размещения и команды ручного запуска, если нужно разобраться в настройке. Для обычного использования достаточно `./run.sh` выше.

Понадобятся Python3, Java (можно `.tools/jdk`), `flock`, nftables, Linux Docker Engine **в той же WSL-дистрибуции**, Tailscale и подключение обоих телефонов к разрешённому tailnet. Docker Desktop не подменяет этот вариант с общей Linux host network. Сервер работает, пока включены ПК, WSL и процессы; сон ПК прервёт связь. Низкоуровневые `deploy/*.sh` не устанавливают пакеты и не входят в аккаунты; верхний `./run.sh` организует эти шаги с подтверждением пользователя. Автозапуск приложения при загрузке ОС не настраивается.

В этой схеме Tailscale работает внутри WSL. Сначала отключите Tailscale на Windows: [официальная инструкция WSL2](https://tailscale.com/docs/install/windows/wsl2) предупреждает о проблемах при одновременной работе обеих копий и обычно рекомендует Windows-only. Для данного размещения намеренно выбран WSL-only, чтобы адрес и media socket находились в одной сетевой среде. На обоих телефонах Tailscale должен быть включён.

Самостоятельно установите зависимости, запустите Docker/Tailscale и авторизуйте WSL-узел. Включите MagicDNS и HTTPS для tailnet; у узла должны быть свободны Serve443/8443. Для двух телефонов разрешите доступ к WSL-узлу: TCP443,8443,7881 и UDP7882. Ограничьте grants/ACL конкретными доверенными пользователями/устройствами: стандартный tailnet может разрешать доступ всем своим участникам. Проброс портов роутера и Funnel не нужны.

Узнайте IPv4 и полный DNSName именно WSL-узла:

```bash
tailscale ip -4
tailscale status --json
```

Скопируйте `Self.DNSName`, убрав завершающую точку. Следующие команды выполняются пользователем позже; замените пример адресов своими:

```bash
bash deploy/setup.sh ryadom.example-tailnet.ts.net 100.100.100.100
./gradlew :server:installDist
sudo nft -f deploy/tailnet-only.nft
sudo nft list table inet ryadom_media
RYADOM_MEDIA_FIREWALL_CONFIRMED=yes bash deploy/start.sh
```

Перед запуском убедитесь, что таблица содержит обе drop-правила для media-портов вне `tailscale0`/`lo`. Флаг — ваше подтверждение установленного фильтра, не автоматическая проверка firewall. При уже существующей таблице не применяйте файл повторно: проверьте её содержимое. Таблица не делает полную настройку firewall и не сохраняется автоматически после перезапуска WSL; после него примените и проверьте её снова.

`setup.sh` отказывается перезаписывать существующий `deploy/state/`. Он создаёт случайные ключи и приватные файлы (каталог700, файлы600):

- `server.env`: `RYADOM_INSTALL_KEY`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `LIVEKIT_URL=wss://<DNSName>` и `LIVEKIT_INTERNAL_URL=http://127.0.0.1:7880`.
- `livekit.yaml`: `rtc.node_ip=<100.x адрес>`, `use_external_ip=false`, фильтры кандидатов `tailscale0` и `/32`, максимум два участника.
- `bootstrap-uri.txt`: приватная ссылка `ryadom://setup?server=<кодированный HTTPS URL:8443>&key=<installKey>`; скрипт также выводит её в терминал. История/вывод терминала тоже приватны.

Откройте эту ссылку на доверенном телефоне с установленным APK либо внесите сервер и ключ в экран настройки приложения. Получатель ключа может создавать комнаты. Ключ LiveKit остаётся на сервере; APK его не содержит. Передавайте приглашение комнаты второму человеку через доверенный канал.

`start.sh` запускает закреплённый [LiveKit v1.13.7](https://github.com/livekit/livekit/releases/tag/v1.13.7) в Docker host network и Ktor через `server/build/install/server/bin/server`. Ktor слушает `127.0.0.1:8080`, LiveKit signalling — `127.0.0.1:7880`. Две непостоянные сессии [Tailscale Serve](https://tailscale.com/docs/reference/tailscale-cli/serve) дают private HTTPS443 → LiveKit и HTTPS8443 → Ktor; WebSocket использует443. Media идёт напрямую через UDP7882 либо TCP7881, не через Serve. [Фильтры LiveKit](https://github.com/livekit/livekit/blob/v1.13.7/config-sample.yaml) ограничивают ICE-кандидаты; они не гарантируют bind TCP socket только к Tailscale, поэтому Linux input firewall обязателен. TURN отключён.

Команда остаётся в терминале. Сообщение о запуске не является проверкой готовности; логи — `deploy/state/*.log`. Остановка: Ctrl+C либо из второго терминала `bash deploy/stop.sh`. Скрипт посылает TERM только своему supervisor с проверкой времени создания PID; тот завершает свои процессы и контейнер по сохранённому ID. Сторонние контейнеры/процессы и чужой Serve config не сбрасываются. После аварийного выключения проверьте `livekit.cid`, Docker и `tailscale serve status` вручную: скрипт не уничтожает неопознанные остатки. Для удаления только подготовленного firewall после остановки: `sudo nft delete table inet ryadom_media`.

Состояние комнат сервера хранится в памяти: перезапуск отменяет приглашения/участников. Для ротации install/API ключей сначала остановите сервисы, сохраните приватную резервную копию `deploy/state/` вне публикаций, затем явно уберите старую конфигурацию и повторите настройку; телефоны настраиваются заново. Не публикуйте `deploy/state/`, bootstrap-ссылки, логи или ключи.

## Контракт и ручная приёмка

Создание приглашения: `POST /rooms` с `Authorization: Bearer <installKey>` → `{roomId,key}`. Вход: `POST /rooms/{roomId}/join`, JSON `{key,identity,name}` → `{serverUrl,token,roomId}`. Короткоживущий токен выдаётся сервером; installKey не равен ключу приглашения. Доступ Tailscale и приглашение комнаты нужны одновременно.

На двух реальных телефонах **в разных сетях** (например Wi-Fi и мобильная), с реальным модом TikTok:

1. Настроить сервер, создать комнату, передать приглашение; проверить голос в обе стороны и чат.
2. Разрешить показ экрана Android, включить ролик в моде: второй телефон видит экран и слышит playback. Проверить «Сигнал звука», одновременно поговорить голосом.
3. Выключить микрофон показывающего: голос исчезает, звук ролика продолжает идти. Включить микрофон обратно.
4. Остановить показ, сменить показывающего и повторить экран/звук/голос.
5. Отозвать показ системной кнопкой Android: захват останавливается, голос и чат остаются доступны; новый показ требует нового согласия.
6. Прервать сеть, восстановить её и проверить переподключение; отдельно проверить отказ третьему участнику и недействительному приглашению.

Если мод запрещает playback capture, нулевой сигнал не исправляется обходом разрешений: отдельно проверьте заведомо разрешённый источник, сохраните результат именно для мода. Компиляция, unit tests и lint не заменяют эту приёмку. Развёртывание WSL/Tailscale, установка APK и реальное аудио/видео здесь пока **UNRUN**.
